## 이후 번호 배포 요청 처리

사용자가 “3번 배포해줘”라고 하면 이 목록의 3번을 대상으로 진행합니다. 여러 번호를 요청하면 위 추천 순서대로 처리합니다. 현재 초안은 공개되지 않았으며 썸네일 이미지는 제작 방향만 준비된 상태입니다.

1. 해당 글의 공식 출처, 현행 법령과 해당 연도 공지를 재확인하고 초안을 필요한 만큼 보강합니다. 제목·메타제목·검색 의도를 유지하고 Quick Answer, 핵심 비교, 문서 체크리스트, FAQ, 공식 출처와 내부 링크를 검토합니다.
2. 배포 당일 Asia/Seoul 날짜를 확인합니다. 과거 초안 날짜를 사용하지 않습니다. npm run promote:guide -- <번호> 는 한국 시간의 실제 실행일을 pubDate, updatedDate, lastReviewed에 반영합니다. 앱에서 확인한 실제 배포일과 실행 환경 날짜가 다르면 --date YYYY-MM-DD로 배포일을 명시합니다.
3. npm run validate:recommended 와 npm run build 를 실행합니다. 공개 페이지의 Last updated, Article dateModified, sitemap, canonical, 메타제목과 OG 정보를 확인합니다.
4. 기존 사용자 변경과 아직 공개하지 않을 글을 함께 배포하지 않도록 대상 변경을 검토합니다. 저장소에서 확인된 Cloudflare Pages 배포 경로를 사용하고 실제 배포 성공 및 공개 URL을 확인한 뒤 완료를 보고합니다. 권한·인증 오류가 있으면 성공으로 표현하지 않습니다.
5. 배포가 다음 한국 날짜로 넘어가면 날짜를 다시 반영해 빌드/배포합니다. 날짜만 바꿔 내용 검토를 대신하지 않습니다.
